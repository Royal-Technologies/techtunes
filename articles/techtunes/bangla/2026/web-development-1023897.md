প্রযুক্তির আজকের এই দ্রুতগতির যুগে আমরা প্রতিনিয়ত কত চমৎকার সব Software এবং Mobile Application ব্যবহার করি, তাই না? অনেক সময়ই কোনো একটি App-এর বিশেষ কোনো Feature বা অসাধারণ Mechanics দেখে আমাদের নিজেদের তৈরি প্রোডাক্টেও সেরকম কিছু যুক্ত করার তীব্র ইচ্ছা জাগে। কিন্তু বাস্তবতা হলো, সেই জনপ্রিয় App-এর কোনো Source Code বা মূল Architecture-এর নথিপত্র আপনার কাছে নেই। কোনো প্রকার Source Code বা নির্দেশিকা ছাড়া একটি কমপ্লেক্স Software-এর ভেতরে ঠিক কী ঘটছে, তা খুঁজে বের করা এতদিন ছিল অত্যন্ত কঠিন, সময়সাপেক্ষ এবং মাথাব্যথার কারণ।

ঐতিহ্যগতভাবে কোনো Compiled Binary বিশ্লেষণ করতে গেলে ডেভেলপারদের ঘণ্টার পর ঘণ্টা Hex Editor, Disassembler, কিংবা Debugger-এর দিকে তাকিয়ে থাকতে হতো। কিন্তু এই ক্লান্তিকর ও জটিল প্রক্রিয়াকে এক মুহূর্তে সহজ ও আনন্দদায়ক করে তুলতে হাজির হয়েছে REA (Reverse Engineer Anything)!

আধুনিক Software Reverse Engineering-এর নতুন দিগন্ত: AI Agent এবং REA দিয়ে যেকোনো Application-এর গোপন রহস্য উদঘাটনের পূর্ণাঙ্গ নির্দেশিকা।

morluto/rea Repository-র অধীনে তৈরি এই Open-Source প্রজেক্টটি বিশ্বজুড়ে Developer, Security Researcher এবং Reverse Engineer-দের কাজের ধরন সম্পূর্ণ বদলে দিয়েছে। REA মূলত এমন একটি জাদুকরী ব্রিজ, যা আপনার নিত্যদিনের প্রিয় AI Agent-কে একজন অত্যন্ত চতুর, অভিজ্ঞ ও নির্ভুল Reverse Engineer-এ রূপান্তর করে। এর মাধ্যমে আপনি সাধারণ Application Behavior পর্যবেক্ষণ করা থেকে শুরু করে প্রসেসরের একদম নিচুতলার Native Binary Level পর্যন্ত যেকোনো কিছু অত্যন্ত সূক্ষ্মভাবে Inspect, Trace এবং Analyze করতে পারবেন।

![REA](https://dnc.techtunes.io/tDrive/tuner/2026/10/techtunes_23349d45e636a57e1ecb350891d36e88.png)

বিশ্বজুড়ে ছড়িয়ে থাকা নানা ভাষার ডেভেলপারদের সুবিধার জন্য REA-এর Documentation অসংখ্য ভাষায় পড়ার সুযোগ রয়েছে। সমর্থিত ভাষাগুলোর মধ্যে রয়েছে English, 简体中文, 繁體中文, 日本語, 한국어, Türkçe, Русский, Tiếng Việt, ไทย, Deutsch, Español, Français, Українська, Polski, Português (Brasil), العربية, فارسی, Bahasa Indonesia, Italiano, Ελληνικά, এবং മലയാളം।

শুধু তাই নয়, বিশ্বব্যাপী রিভার্স ইঞ্জিনিয়ারিংপ্রেমীদের সাথে ভাববিনিময় করা, যেকোনো জটিল প্রশ্ন জিজ্ঞেস করা এবং নিজেদের নতুন নতুন আবিষ্কার শেয়ার করে নেওয়ার জন্য রয়েছে একটি সমৃদ্ধ Discord Community (Discord · Q&A · Show And Tell)।

> অত্যন্ত জরুরি নিরাপত্তা সতর্কবার্তা (Important):  
>  REA পেতে সর্বদা কেবল অফিশিয়াল উৎসগুলোই বেছে নিন: `morluto/rea` GitHub Repository, `rea.tools` Website, অথবা Official `rea-agents` npm Package। কেবল অফিশিয়াল লিঙ্ক থেকেই Installation এবং Release প্রক্রিয়াকরণ অনুসরণ করুন। কোনো মিল থাকা Repository Name কিংবা কপি করা README ফাইল কখনোই কোনো ডাউনলোডের অফিশিয়াল বৈধতা প্রমাণ করে না।

আপনি যদি অন্য কোনো Application-এ এমন একটি চমৎকার Feature দেখেন যা আপনার নিজস্ব Project-এ যুক্ত করতে চান, তবে শুধু আপনার Agent-কে তা REA দিয়ে Investigate করতে বলুন। এটি Source Code ছাড়াই মূল App-টি পরীক্ষা করে ফেলবে, Feature-টি কীভাবে কাজ করে তা একদম পানির মতো সহজ ভাষায় Explain করবে, এর পেছনে থাকা প্রতিটি Evidence প্রমাণ হিসেবে আপনার সামনে তুলে ধরবে, এবং আপনার নিজের Project-এ ব্যবহারের জন্য হুবহু একই কাজের একটি সম্পূর্ণ কার্যকর Code তৈরি করে দেবে!

REA মূলত আপনার AI Agent-কে Native Binaries, JavaScript ও Electron Apps, .NET Assemblies, এবং Websites গভীরভাব পরীক্ষা করার জন্য প্রয়োজনীয় সমস্ত বিশ্বমানের Tools-এর সাথে যুক্ত করে দেয়। আপনি চাইলে একই Tools সরাসরি আপনার নিজস্ব Terminal থেকেও Command দিয়ে ব্যবহার করতে পারেন। সবচেয়ে বড় সুবিধার বিষয় হলো, সম্পূর্ণ Analysis প্রক্রিয়াটি একদম স্থানীয়ভাবে (Locally) আপনার নিজের কম্পিউটারে সম্পন্ন হয়। ফলে আপনার ডেটা থাকে সম্পূর্ণ নিরাপদ এবং প্রতিটি ফলাফলের সাথে স্পষ্ট Evidence ও Limitations উল্লেখ করা থাকে।

Setup প্রক্রিয়ার মাধ্যমে আপনার AI Agent-এর সাথে REA-এর MCP Server যুক্ত হয় এবং সঠিক Workflow Instructions ইনস্টল হয়ে যায়। Native Analysis-এর জন্য আপনার কম্পিউটারে ইতোমধ্যে থাকা Hopper, Ghidra, বা IDA ব্যবহার করা যায়; এমনকি Setup প্রক্রিয়া আপনার অনুমতির ভিত্তিতে Hopper নিজে থেকেই ইনস্টল করে দেওয়ার ক্ষমতা রাখে। তবে চমৎকার বিষয় হলো, Static JavaScript Analysis করার জন্য কোনো Native Analysis Engine-এর দরকারই পড়ে না!

## Quick Start: আপনার Agent এবং Terminal অত্যন্ত সহজে কনফিগার করার নিয়ম

![আপনার Agent এবং Terminal অত্যন্ত সহজে কনফিগার করার নিয়ম](https://dnc.techtunes.io/tDrive/tuner/2026/10/techtunes_291e86f9a9c5a51cae1f37f7c99e9f06.jpg)

আপনি যদি Linux Operating System ব্যবহারকারী হন, তবে মনে রাখবেন— Ghidra, JADX, Firmware Tool Launches এবং Static JavaScript/Electron Analysis চালানোর সময় Process Ownership Checks সফলভাবে সম্পন্ন করতে REA-এর `PATH`-এ একটি Procps-Compatible `ps` থাকা আবশ্যক। কোনো কারণে সমস্যা হলে `docs/installation.md` ফাইলের "Linux owned-process prerequisite" অংশ থেকে Recovery Steps দেখে খুব সহজেই সমাধান করে নিতে পারবেন।

### Set Up Your Agent

আপনার কম্পিউটারে Node.js এবং npm ইনস্টল করা থাকলে, আপনার AI Agent-কে REA-এর সাথে সংযুক্ত করতে Terminal-এ নিচের Command-টি রান করুন:

```
npx rea-agents setup
```

এই সহজ Command-টি রান করার পর স্ক্রিনে আপনার ব্যবহৃত Agent নির্বাচন করার অপশন আসবে। আপনার সিলেক্ট করা Agent অনুযায়ী প্রজেক্টটি কিছু পরিবর্তন করার প্রস্তাব দেবে। প্রস্তাবিত Changesগুলো ভালোভাবে Review করে Approve করে দিন। Setup সিস্টেমটি স্বয়ংক্রিয়ভাবে REA-এর MCP Server এবং মানানসই Workflow Instructions যোগ করবে এবং আপনার বিদ্যমান সব Configuration-এর একটি নিরাপদ Backup তৈরি করে রাখবে। সবশেষে কেবল আপনার Agent-টি একবার Restart করে নিন।

REA বর্তমানে বাজারসেরা প্রায় সকল AI Agent সাপোর্ট করে, যার মধ্যে রয়েছে Claude Code, Codex, Cursor, Gemini CLI, Grok Build এবং আরও অন্যান্য Agent (`docs/installation.md#supported-agents`)। অন্যান্য অজানা Provider Configuration এবং ম্যানুয়ালি রেজিস্ট্রেশন করার পদ্ধতি জানতে Installation And Setup গাইডটি দেখে নিন।

### Ask Your Agent

Agent সেটআপ হয়ে গেলে তার সাথে কথা বলা কতটা সহজ, তা এই উদাহরণটি দেখলেই বুঝতে পারবেন। আপনি আপনার Agent-কে ঠিক এভাবে লিখতে পারেন:

```
Understand how search works in the Notes app, show me the evidence, and build a similar feature for my project.
```

*(উপরের প্রম্পটে "Notes" শব্দের জায়গায় আপনার কাঙ্ক্ষিত Target App-এর নাম এবং "search"-এর জায়গায় আপনি যে নির্দিষ্ট Feature রিভার্স ইঞ্জিনিয়ারিং করতে চান তা বসিয়ে দিন। )*

### Use The Terminal

আপনি যদি AI Agent-এর সাহায্য ছাড়া নিজে সরাসরি Terminal থেকে কোনো Unpacked JavaScript/Electron App Directory কিংবা ASAR File পরীক্ষা করতে চান, তবে অত্যন্ত সহজ একটি Command দিয়ে তা করতে পারেন:

```
npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app -json
```

এই Command-টি চালানোর সাথে সাথে রেজাল্ট হিসেবে ওই অ্যাপের সমস্ত Modules, Imports, Electron Boundaries এবং তাদের সপক্ষের মজবুত Evidence চলে আসবে। Path-টি আপনার ফাইলের সঠিক স্থান দিয়ে বদলে দিন (যেমন Windows-এর জন্য `"D:/apps/example"`)।

দৈনন্দিন ব্যবহারের জন্য `rea` Command-টি globally Install করে নিতে পারেন:

```
npm install -global rea-agents
rea -help
```

স্মরণ রাখবেন, Native Analysis করার পূর্বে আপনাকে একটি নির্দিষ্ট Provider কনফিগার করে নিতে হবে। Native Commands, Provider Selection, Snapshots এবং Scripting-এর যাবতীয় খুটিনাটি জানতে CLI And Evidence Guide পঠন করুন।

### Update REA

REA প্রজেক্টটির ওপর প্রতিনিয়ত নতুন নতুন ফিচার যোগ করা হচ্ছে এবং নিত্যনতুন Bug Fixes আসছে। তাই ভালো পারফর্ম্যান্স পেতে আপনার ইনস্টলেশনটি সব সময় Up to Date রাখা অত্যন্ত গুরুত্বপূর্ণ।

আপনি যদি `npm install -global` বা `bun add -global` দিয়ে CLI ইনস্টল করে থাকেন, তবে আপডেট করতে রান করুন:

```
rea update
```

আপনার জানা থাকা ভালো যে `rea -update` মূলত এই একই কাজের একটি Alias এবং এটি সব ধরনের Global Output Flags সমর্থন করে। অন্যান্য Command Controls-এর সাথে কাজ করার সময় সরাসরি `rea update` ব্যবহার করা সবচেয়ে নিরাপদ।

Updater Command-গুলো চমৎকারভাবে তাদের স্মৃতিশক্তি ব্যবস্থাপনা করে। এটি একসাথে সর্বোচ্চ 4 MiB পরিমাণ Stdout এবং Stderr সমন্বিতভাবে ধরে রাখতে পারে। Command শেষ হয়ে বের হয়ে যাওয়ার পর যদি কোনো Oversized Metadata Replies আসে, তবে সিস্টেম তা সাথে সাথে রিজেক্ট করে দেয়। এমনকি Verbose Installs-এর ক্ষেত্রেও এটি সীমিত সীমার Diagnostics নিয়ে সুরক্ষিতভাবে চলতে থাকে। সাধারণ মানুষের জন্য স্ক্রিনে দেখানো Progress Output মূলত টার্মিনাল Backpressure-এর নিয়ম মেনে চলে এবং Submitted Write সম্পূর্ণ শেষ হওয়া পর্যন্ত ধৈর্য ধরে অপেক্ষা করে।

Bun ব্যবহারকারীদের জন্য বিশেষ দ্রষ্টব্য— Bun দিয়ে Global Updates করার জন্য আপনার কম্পিউটারে Bun 1.2.17 বা তার পরবর্তী Version ইনস্টল থাকা চাই। পুরোনো Bun Release থাকলে, `rea update` Command চালানোর আগেই ম্যানুয়ালি Bun Upgrade করে নিন।

আপডেটের পর আপনার Agent-এর সাথে Registrations এবং Skill রিফ্রেশ করতে স্ক্রিনে ভেসে ওঠা নির্দিষ্ট Setup Command-টি নতুন করে আবার রান করুন।

আর আপনি যদি `npx` ব্যবহারকারী হন, তবে আপনার Agent Setup আপডেট করতে লিখুন:

```
npx rea-agents@latest setup
```

পরিবর্তনগুলো দেখে নিয়ে আপনার Agent-টি Restart দিন। কোনো বিশেষ এককালীন CLI Commands রান করতে চাইলে `npx rea-agents@latest`-এর সাথে নির্দিষ্ট Command যুক্ত করে দিন। Bun ব্যবহারকারীরা `npx rea-agents@latest`-এর জায়গায় নির্দ্বিধায় `bunx rea-agents@latest` ব্যবহার করতে পারবেন।

## How REA Works: পেছনের ইন্টারেক্টিভ ওয়ার্কফ্লো

![How REA Works: পেছনের ইন্টারেক্টিভ ওয়ার্কফ্লো](https://dnc.techtunes.io/tDrive/tuner/2026/10/techtunes_83c695f3a93086fb855933356f10073d.jpg)

আসুন এবার জেনে নিই REA কীভাবে আপনার Agent-এর সাথে মিলে কাজ সম্পন্ন করে!

প্রথমেই আপনার Agent MCP বা Model Context Protocol-এর সাহায্যে REA-কে নির্দেশ পাঠায় Target File Inspect করার জন্য এবং প্রয়োজনীয় Code Trace করার জন্য। REA তার শক্তিশালী Analysis Tools ব্যবহার করে গভীরে প্রবেশ করে এবং যা যা খুঁজে পায়, তা শক্ত প্রমাণ বা Evidence সহ Agent-এর কাছে উপস্থাপন করে।

আপনার Agent তখন প্রাপ্ত ডেটাগুলো বিশ্লেষণ করে। তার যদি আরও কোনো সন্দেহ থাকে, তবে সে REA-কে আরও গভীরে গিয়ে Follow-up Questions জিজ্ঞেস করে, কোডের মূল Behavior ব্যাখ্যা করে, কিংবা আপনার প্রজেক্টের জন্য নিখুঁত একটি Implementation লিখে ফেলে এবং টেস্ট করে নিশ্চিত হয়। Terminal-এর CLI Commands-ও ঠিক একই শক্তিশালী Workflows মেনে কাজ করে।

চাইলে এর সম্পূর্ণ চিত্ররূপ দেখতে অফিশিয়াল সাইট থেকে Full-Size Architecture Figure-টি দেখে নিতে পারেন।

## What You Can Analyze: বিশ্লেষণের বিশাল পরিধি ও সামর্থ্যের তালিকা

![What You Can Analyze](https://dnc.techtunes.io/tDrive/tuner/2026/10/techtunes_a9d39864549127b75b45d5e937589a7d.jpg)

REA সফলভাবে পরিচালনা করার জন্য আপনার কম্পিউটারে Node.js 22.x (>=22.19), 24.x (>=24.11), অথবা 26+ এবং তার সাথে npm থাকা আবশ্যক। আপনি ঠিক কোন ধরনের ফাইল বা সিস্টেম পরীক্ষা করছেন, তার ওপর ভিত্তি করে প্রয়োজনীয় Tools এবং Requirements আলাদা হতে পারে। নিচে ২৩টি প্রধান Analysis Targets-এর বিস্তারিত তালিকা দেওয়া হলো:

| Target | What REA Returns | Requirements And Guide |
| --- | --- | --- |
| Native Binaries | Pseudocode, Assembly, Strings, Symbols, Calls এবং References। | Hopper, Ghidra অথবা IDA; `native-investigation.md` |
| Offline ELF Layout | Sections, Segments, Original Symbols/Relocations এবং Static Mitigation Candidates। | Linux x64-এ Caller-Supplied Pwntools; `binary-diagnostics.md` |
| Go Binaries | Embedded Compiler Version, Modules, Replacements এবং Build Settings। | Built-In Static ELF/PE/Thin Mach-O Inspection (কোনো Go Installation-এর প্রয়োজন নেই) |
| Rust Binaries | Embedded Cargo-Auditable Crate Names, Versions, Sources এবং Dependency Edges। | Built-In Static ELF/PE/Thin Mach-O Inspection; `rust-binaries.md` |
| WASM Artifact | Validation, Sections, Exact Import/Export WAT Forms এবং Decoded WAT। | Caller-Supplied WABT 1.0.42; `inspect_wasm_artifact` |
| EVM Bytecode | Dispatch Selectors, Byte Offsets, Inferred Arguments এবং Mutability। | Linux x64-এ Local Raw/Hex Carrier; `evm-bytecode.md` |
| SQLite Databases | Tables, Columns, Indexes, Views, Triggers এবং সিলেক্টেড Ordinary-Table Rows। | Local Database/WAL Snapshot; Node.js 24.x >=24.15 বা 26+ সহ Native SQLite Limits |
| Recorded Linux Crashes | Raw Notes, প্রতি Recorded Thread-এর Registers/Signals এবং Optional Mapping Candidates। | Linux x64-এ Caller-Supplied Pwntools; ঐচ্ছিক GDB/Pwndbg; `recorded-crashes.md` |
| JavaScript / Electron | Modules, Imports, Source Maps, Routes, IPC এবং Native Add-On Relationships। | Node.js এবং npm; Linux: Procps-Compatible `ps`; `javascript-application-workflows.md` |
| Websites | Page Structure, Scripts, Network Observations এবং Requested Screenshots। | একটি Chrome-Family Browser; `browser-observation.md` |
| Saved Network Captures | Requests, Responses, Exposed Payloads এবং Source Locations। | HAR অথবা Fiddler Everywhere SAZ; Linux-এ Native Mitmproxy-এর জন্য Mitmdump; `web-network-captures.md` |
| .NET Assemblies | Metadata, CIL Instructions, Declared Native Dependencies এবং Build Comparisons। | None (Static Only); `managed-code-analysis.md` |
| Android APKs | Manifest Declarations, Classes, Decompiled Methods এবং References। | Linux/macOS/Windows x64-এ Headless JADX এবং Full JDK; `android-analysis.md` |
| Android Devices | Devices, Packages, Processes, Logs, Dumps, Screen Captures, এবং APK/File Transfers। | Caller-Supplied ADB (Emulator অথবা Hardware); `adb-device-analysis.md` |
| JEB Projects | Engine-Backed Project Units, Artifact Digests এবং Type/Method Pseudo-Code। | `REA_JEB_MCP_URL` দিয়ে সিলেক্ট করা MCP Serve করা Caller-Started JEB Client; `jeb-analysis.md` |
| Android Resources | Decoded Manifest, String Tables, Locales এবং Version Facts। | Caller-Supplied Apktool Launcher; `apktool-resource-analysis.md` |
| Flutter Apps | Dart Snapshot Hash, Per-ABI Library Digests এবং Engine Build Provenance। | None (Static APK Parsing); `flutter-analysis.md` |
| Firmware | Regions, Extraction Results এবং Native-Analysis Handoffs। | Linux-এ Binwalk / Unblob; `firmware-analysis.md` |
| Recorded Packets | Selected Fields, Repeated Values, Filters এবং Decode-As Rules। | Linux: TShark 4.x + Prlimit; `packet-captures.md` |
| Packet Summaries | Endpoints, DNS, TLS SNI, Protocol Distribution এবং HTTP Requests। | Caller-Supplied TShark এবং Capinfos (Linux-Verified); `pcap-analysis.md` |
| Recorded Logic Signals | Decoder Annotations, Sample Ranges এবং Diagnostics। | Linux: Sigrok-Cli 0.7.2 + Prlimit; `signal-recordings.md` |
| Packages And Resources | File Inventories, Digests, Plists, Apple Bundle Anatomy এবং Extracted Resources। | `javascript-artifact-reconstruction.md`, `apple-application-analysis.md` |
| Process Behavior | Terminal Output, Interactions, Exit, Filesystem Observations, এবং Run Comparisons। | Native PTY সহ Linux/macOS; `process-capture.md` |

প্রসঙ্গক্রমে জানিয়ে রাখা ভালো— Static JavaScript এবং.NET Inspection কোনো Application রান না করেই সরাসরি সরবরাহ করা ফাইলগুলো স্ক্যান করে ফেলে। অন্যদিকে Runtime Capture ব্যবস্থাটি আপনার নিজস্ব User Permissions ব্যবহার করে নির্বাচিত Target Run করে বা তার সাথে লেনদেন করে। প্রতিটি Runtime Guide-এ এর বিস্তর প্রভাব আলোচনা করা হয়েছে।

অফলাইন Native-Binary Inspection করার সুবিধার্থে REA ব্যবহারকারীর মেশিনে থাকা GNU Objdump এবং Rizin-ও সাপোর্ট করে। Provider Setup, CLI Commands, এবং Evidence Limitations জানতে `reverse-engineering-tools.md` দেখে নিন (তবে মনে রাখবেন REA নিজে এই দুই টুলের কোনোটি ইনস্টল বা আপডেট করে না)।

বিভিন্ন Provider-এর ওপর ভিত্তি করে Native Formats এবং Host Support আলাদা হতে পারে। Hopper And Ghidra Setup, IDA Guide (Optional Native MCP Bridge সহ), Kuna Decompiler Guide, এবং Experimental Windows Ghidra Support গাইডগুলো দেখে নিন। এমনকি Ghidra দিয়ে 16-Bit DOS Analysis-ও করা সম্ভব! বিশাল কোনো Binary ফাইল বিশ্লেষণ করার সময় Decompiler Engine যাতে Timeout না মারে, সেজন্য স্ক্রিপ্টে Startup Deadline বাড়িয়ে দিতে পারেন এই দুটি Environment Variables ব্যবহার করে:

- `REA_GHIDRA_STARTUP_TIMEOUT_MS`
- `REA_HOPPER_STARTUP_TIMEOUT_MS`

লেটেস্ট npm Release-এর পর নতুন যেসব ফিচার যোগ করা হয়েছে, তা জানতে অফিশিয়াল প্রজেক্টের Release Availability অপশনটি নিয়মিত চেক করুন।

### DX-Ball: Reconstruct a Sound-Pan Calculation

একটি ক্লাসিক গেমের Sound Call অনুসরণ করে এর Position-to-Pan Helper ফাংশনে প্রবেশ করা হয়। এর কঠিন Instructions পর্যালোচনা করে অসম্পূর্ণ Pseudocode-কে রূপান্তর করা হয় নিখুঁত C Code-এ। আশ্চর্যজনক বিষয় হলো, নতুন তৈরি করা এই C Code Reconstruction-টি মূল x86 Architecture-এর ৩, ২০৫টি Test Cases সফলভাবে পাস করেছে এবং ফাইলটির সমস্ত ৬৩টি Compiled Function Bytes হুবহু রিপ্রোডিউস করতে সক্ষম হয়েছে!

### Notion: Trace The Electron Clipboard Bridge

Notion App-এর Renderer Process-এর ভেতরে থাকা Clipboard API খুঁজে বের করে, তাকে Preload এবং IPC-এর জটিল পথ পার করে Main Process পর্যন্ত ট্র্যাক করা হয়। এর মাধ্যমে Notion-এর Rich Clipboard Format কীভাবে কাজ করে তা সফলভাবে রিভার্স ইঞ্জিনিয়ারিং করা সম্ভব হয়েছে।  
 *(Case Study পড়ুন: `rea.tools/showcase/notion/`)*

### TH04: Recover a DOS Bullet-Ring Calculation

মূল PC-98 Platform-এর পুরোনো গেমের ১৬-বিটের Instructions গভীরে গিয়ে স্ক্যান করা হয়। সেখান থেকে গেমের Bullets-এর Fixed এবং Aimed Angle Calculations উদ্ধার করে নতুন C+ কোড লেখা হয় এবং ঐতিহাসিক Compiler Output-এর সাথে মিলিয়ে নির্ভুলতা প্রমাণ করা হয়।  
 *(Case Study পড়ুন: `rea.tools/showcase/th04/` · Reconstruction Repository: `github.com/N0zoM1z0/th04`)*

আপনি নিজেও যদি REA ব্যবহার করে মজাদার বা দরকারী কোনো প্রজেক্ট বিশ্লেষণ করে থাকেন, তবে একটি Issue বা Pull Request খুলে আপনার Target, প্রশ্ন, REA কীভাবে সাহায্য করল এবং কী চমৎকার ফলাফল পেলেন তা লিখে জমা দিয়ে দিন!

## FAQ: মনে জাগা প্রশ্নগুলোর বিস্তারিত উত্তর

![মনে জাগা প্রশ্নগুলোর বিস্তারিত উত্তর](https://dnc.techtunes.io/tDrive/tuner/2026/10/techtunes_e88bae5c0868ec2b3938d7d5176e68e0.jpg)

### Which agents can use REA?

Local MCP Servers সমর্থন করে এমন যেকোনো AI Agent দিয়ে REA ব্যবহার করা যাবে। Setup রান করলে এটি জনপ্রিয় সমর্থিত Agent-গুলো নিজে থেকেই কনফিগার করে দেয়। অন্যান্য কোনো বিশেষ Client থাকলে তা Manual MCP Registration পদ্ধতি ব্যবহার করে যুক্ত করা যায়।

### Do I need Hopper, Ghidra or IDA?

Deep Native Analysis-এর জন্য এদের যেকোনো একটি প্রয়োজন হবে। তবে আপনি যদি কেবল Static JavaScript বা.NET Inspection করতে চান, তবে কোনো Native Analysis Engine ছাড়াই REA দুর্দান্ত কাজ করবে। Setup চলাকালীন অনুমতির ভিত্তিতে এটি Hopper ইনস্টল করার সুবিধা দেয়; আর Ghidra ও IDA আপনার পিসিতে আগে থেকে ইনস্টল করা থাকলে তা স্বয়ংক্রিয়ভাবে ব্যবহার করে।

### Do I need to start Hopper first?

একদমই না! REA-এর যখনই প্রয়োজন পড়বে, সে নিজ দায়িত্বে Hopper চালু করে নেবে। তবে macOS ব্যবহারকারীদের ক্ষেত্রে প্রথমবার রান করার সময় Demo Mode বা License Activate করার একটি Pop-Up ডায়ালগ আসতে পারে। আপনার প্রথম CLI/MCP Operation পরিচালনা করার আগেই একই User Session-এ সেই প্রম্পটটি পূরণ করে ফেলুন। প্রয়োজনে প্রথমবার ম্যানুয়ালি Hopper ওপেন করে প্রম্পট সরাতে পারেন।

### What does installing the skill from skills.sh do?

এই Skill-টি মূলতঃ আপনার Agent-কে রিভার্স ইঞ্জিনিয়ারিং করার জন্য নিখুঁত Investigation Instructions বা দিকনির্দেশনা প্রদান করে। `npx rea-agents setup` ব্যবহার করে REA-এর MCP Server এবং সাথে মানানসই নির্দেশাবলী ইনস্টল করে নিন, তারপর কেবল Agent-টি Restart দিন।

### What code does REA return?

Native Analysis করার পর এটি আপনাকে উপহার দেবে Pseudocode এবং Assembly Code। আর JavaScript/Electron Analysis করার ক্ষেত্রে এটি খুঁজে বের করবে অ্যাপের আসল Modules এবং তাদের পারস্পরিক যোগাযোগের মানচিত্র। আপনার AI Agent এই ফলাফলগুলোকে পুঁজি করে সম্পূর্ণ নতুন Code লিখতে ও টেস্ট করতে পারে।

### Does REA upload my app?

কখনোই না! REA ১০০% স্থানীয়ভাবে (Locally) আপনার নিজের কম্পিউটারে সমস্ত Analysis রান করে। আপনার কোনো ফাইল বা অ্যাপ কোথাও আপলোড হয় না। কেবল বিশ্লেষণের পর যে টেক্সট ফলাফল বা Findings আসে, তা আপনার Agent পায় (যার ডেটা পলিসি সম্পূর্ণ নির্ভর করে আপনার ব্যবহৃত Agent Model Provider-এর ওপর)।

### What should I do if I hit a bug?

কাজে কোনো সমস্যা বা Bug পেলে শুরুতেই REA আপডেট করে নিন, কারণ নতুন কোনো Release-এ হয়তো সেই সমস্যার সমাধান অলরেডি চলে এসেছে!  
 CLI ব্যবহারকারীরা আপডেট করতে লিখুন: `rea update`  
 `npx` ব্যবহারকারীরা Agent Setup আপডেট করতে লিখুন: `npx rea-agents@latest setup`  
 আপডেট শেষে আপনার Agent Restart করে একই কাজ আবার চেষ্টা করুন। তারপরও যদি সমস্যা থেকে যায়, তবে আপনার REA Version, Target Type, সমস্যা তৈরির Steps এবং Error Output উল্লেখ করে GitHub-এ একটি Issue ফাইল করুন।
